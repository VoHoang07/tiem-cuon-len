## 1. SYSTEM ARCHITECTURE & TECH STACK

- **Hosting & Edge:** Vercel (`vercel.json` + Serverless Functions tại `api/*.js`) + Cloudflare (`CLOUDFLARE_SECURITY_GUIDE.md` — WAF, DNS, SSL/TLS Full Strict, Rate Limiting).
- **Database & Auth:** Supabase (`src/services/supabase.ts` cho Client/Anon session; `api/_securityCore.js` cho Server-side REST/Service-Role verification; PostgreSQL Row Level Security đã bật toàn diện tại `supabase/migrations/20261104_rls_security_hardening.sql`).
- **Payment Integration:** SePay (`api/sepay-webhook.js`, `src/app/payment/[orderId].tsx`, `src/app/payment-methods.tsx`, `src/store/PaymentMethodsContext.tsx` — VietQR / Webhook tự động xác nhận giao dịch chuyển khoản ngân hàng).
- **Order & Authoritative Pricing Pipeline:**
  - Server-side Order Guard & Price Calculator: `api/orders-guard.js`
  - Client Order Store & Sync: `src/store/OrderContext.tsx`, `src/app/checkout.tsx`, `src/app/orders/index.tsx`, `src/app/orders/[id].tsx`
  - Server-side Email Notification Dispatch: `api/_securityCore.js` (`sendOrderNotificationServer`), `src/utils/sendOrderNotification.ts`
- **Security Stack:**
  - **HTTP Security Headers (CSP, HSTS, CORS, X-Frame-Options, Permissions-Policy):** `vercel.json` & `api/_securityCore.js` (`applySecurityHeaders`, `verifyCsrfOrigin`, `setHardenedSessionCookie`)
  - **Rate Limiter Middleware & Bot Guard:** `src/utils/securityGuard.ts` (Client Sliding-Window Rate Limiter) & `api/_securityCore.js` (`checkServerRateLimit`, `enforceNotBlockedIp`)
  - **Request Audit Logger (SIEM) & HMAC-Signed IP Blocklist:** `api/security-audit.js`, `api/_securityCore.js`, `src/app/privacy.tsx`
  - **Form Honeypot Validation (Hidden Bot Trap):** `src/components/HiddenBotField.tsx` & `src/utils/securityGuard.ts` (`validateHiddenBotField`)
  - **Strict Schema Validation (Anti-Mass-Assignment) & XSS Sanitizer:** `src/utils/schemaValidator.ts` & `api/_securityCore.js` (`stripUnknownFieldsServer`, `sanitizeTextServer`)
  - **File Upload Guard (Magic Bytes + Max Size + UUID v4 Rename):** `src/utils/fileUploadGuard.ts` & `src/components/ProductStudioForm.tsx`
- **Verification Commands:**
  - Kiểm tra bảo mật tự động (Quét lộ Secret/API Key, Global Error Handler, Anti-Mass-Assignment, Magic Bytes, HTTP Headers, `npm audit`): `npm run security:check` (hoặc `npm run security:scan`)
  - Quét lỗ hổng thư viện Production: `npm run security:audit` (`npm audit --omit=dev --audit-level=high`)
  - Build kiểm tra bundle Web thực tế (Vercel Web Export): `npm run build:web` (`npx expo export -p web`)

## 3. QUY TRÌNH THỰC THI 3 PHA (PLAN -> EXECUTE -> VERIFY)

- **Pha 1 (Plan):**
  - Phân tích yêu cầu, kiểm tra xem có chạm vào **Critical Paths (Mục 2)** hay vi phạm **Self-Evolving Memory (Mục 4)** không.
  - Đề xuất phương án ngắn gọn trước khi sửa nhiều file.
- **Pha 2 (Execute):**
  - **Đồng bộ toàn diện Client + Admin & Desktop + Mobile:**
    1. Luôn cập nhật đồng bộ cả luồng Khách hàng (`customer`) và Quản trị (`admin`) trong cùng 1 lần sửa.
    2. Kiểm tra và tối ưu bố cục cho cả màn hình Desktop (`>= 768px`) lẫn Mobile (`< 640px`, chiều rộng `360px–430px`). Trên Mobile: căn lề chuẩn (`paddingHorizontal: 12`), dùng `flexWrap: 'wrap'` cho các hàng nút, dùng `minWidth: 0` cho `TextInput` trong hàng ngang, và đảm bảo không có phần tử nào bị tràn mép phải hoặc bị `BottomNav` che khuất.
  - **Tối ưu Supabase:** Chỉ `.select()` đúng các cột cần thiết, tuyệt đối tránh `select('*')` không giới hạn và lỗi N+1 query.
  - **Chuẩn UX:** Mọi thao tác bất đồng bộ (thêm giỏ hàng, tạo mã QR SePay, lọc sản phẩm, lưu nháp sản phẩm) bắt buộc phải có đầy đủ 3 trạng thái: `Loading/Skeleton`, `Success`, và `Error handling` rõ ràng.
- **Pha 3 (Verify):**
  - Sau khi sửa code, BẮT BUỘC tự chạy lệnh kiểm tra bảo mật & build (`npm run security:check` / `npm run build:web`) trên terminal. Nếu có lỗi đỏ, phải tự đọc log và sửa đến khi Pass 100% mới kết thúc.

## 4. SELF-EVOLVING MEMORY (BỘ NHỚ TỰ HỌC TỪ BUG)

> **[QUY TẮC BẮT BUỘC]:** Trước khi code phải đọc mục này. Sau mỗi lần fix bug (do người dùng báo hoặc do lệnh build/test bắt được), AI phải tự động ghi nối thêm 1 quy tắc mới vào dưới đây theo định dạng: `[Phân hệ] Triệu chứng lỗi -> Nguyên nhân gốc -> Luật bất khả kháng`.

1. **[Product & Storage Quota Sync]** Thêm sản phẩm mới có nhiều ảnh phân loại HD (12 cung hoàng đạo / 34 màu len) bị mất dữ liệu sau khi tải lại trang hoặc không đồng bộ từ máy tính Admin sang điện thoại Khách -> `localStorage` của trình duyệt chỉ có giới hạn ~5MB nên ném lỗi `QuotaExceededError` khi lưu mảng ảnh Base64 lớn, đồng thời `cart_items`/`orders` lưu nguyên chuỗi ảnh Base64 của toàn bộ biến thể làm phình payload Supabase -> **Luật bất khả kháng:** Mọi dữ liệu sản phẩm và bản nháp Admin (`ProductContext.tsx`, `productDraftStore.ts`) bắt buộc lưu trữ qua `IndexedDB` (`tcl_products_idb_v1`) kết hợp đồng bộ Supabase; khi lưu `cart_items` hoặc `orders` chỉ lưu ảnh đại diện của đúng phân loại khách chọn (`compactOrderItems`), tuyệt đối không nhúng toàn bộ `gallery` và `colorOptions` vào đơn hàng.
2. **[Order & Cart Price Integrity]** Giá sản phẩm sau khi Admin chỉnh sửa bị nhảy về giá cũ trong giỏ hàng, hoặc kẻ tấn công sửa `price`/`total` trong request tạo đơn hàng -> Giỏ hàng rehydrate từ `localStorage` ghi đè lên giá mới trong DB và API tạo đơn tin tưởng trường `total` từ Client gửi lên -> **Luật bất khả kháng:** `CartContext` phải luôn đồng bộ lại đơn giá từ danh mục sản phẩm mới nhất; ở tầng Backend (`api/orders-guard.js` và `api/sepay-webhook.js`), mọi phép tính tiền hàng, phí vận chuyển, giảm giá Freeship (`>= 199.000đ`) và tổng thanh toán bắt buộc tính lại 100% từ Database trên Server (`computeServerAuthoritativePricing`).
3. **[Security & IP Blocklist Integrity]** Kẻ tấn công có nguy cơ chèn IP giả hoặc dải mạng (`0.0.0.0/0`, `::/0`) vào bảng blocklist để khóa toàn bộ khách hàng truy cập web, hoặc đọc trộm nhật ký SIEM từ Client -> Khoá phân vùng (`HOLDER_USER_ID`) dùng chung với cấu hình công khai và dòng blocklist không có chữ ký xác thực Server -> **Luật bất khả kháng:** Phân vùng SIEM (`__TCL_SECURITY_AUDIT_LOG_V1__`) và Blocklist (`__TCL_SECURITY_BLOCKLIST_V1__`) chỉ được truy cập ở tầng Server (`api/`), bị chặn `SELECT/WRITE` đối với `anon` bằng RLS (`supabase/migrations/20261104_rls_security_hardening.sql`); mọi bản ghi chặn IP bắt buộc phải là địa chỉ IP đơn lẻ đã ký `HMAC-SHA256` bằng khoá bí mật Server (`signBlocklistEntry` / `verifyBlocklistEntry`), tuyệt đối cấm chặn theo CIDR/vùng địa lý từ phía ứng dụng.
4. **[Polling & Delete Race Condition]** Khi Admin xoá đơn hàng hoặc cuộc trò chuyện Chat, mục vừa xoá tự động xuất hiện lại sau vài giây -> Chu kỳ polling nền (`setInterval` đang bay trên mạng) trả về dữ liệu cũ sau khi lệnh `delete` vừa chạy xong và ghi đè lại vào React state -> **Luật bất khả kháng:** Trong `OrderContext.tsx` và `ChatContext.tsx`, bắt buộc duy trì tập hợp `deletedIdsRef` (`Set<string>`) và kiểm tra lọc bỏ các ID đã xoá trước khi merge kết quả từ mọi lệnh fetch/poll bất đồng bộ.
5. **[React Hooks Order & Early Return Crash]** Trang Quản lý kho sản phẩm (`manage-products.tsx`) bị văng lỗi trắng trang (`Rendered more/fewer hooks than expected`) khi chuyển đổi tài khoản hoặc reload -> Đặt các hook `useMemo` / `useEffect` nằm phía sau câu lệnh `if (role !== 'admin') return ...` -> **Luật bất khả kháng:** Toàn bộ React Hooks (`useState`, `useMemo`, `useCallback`, `useEffect`, `useFocusEffect`) bắt buộc phải khai báo ở đầu Component trước bất kỳ câu lệnh `if (...) return` kiểm tra quyền truy cập (`role !== 'admin'`) hoặc trạng thái `isLoading` nào.
6. **[Checkout & Notification Timing]** Shop nhận được email báo đơn hàng mới ngay cả khi khách chọn chuyển khoản QR nhưng chưa quét mã thanh toán, hoặc khách bấm nút Thanh toán khi chưa có địa chỉ mà không thấy phản hồi -> Gọi hàm gửi email ngay lúc khởi tạo đơn `pending_payment` và khoá cứng `disabled={!hasAddress}` trên nút đặt hàng khiến khách bấm không có tín hiệu -> **Luật bất khả kháng:** Đơn COD gửi thông báo ngay khi đặt, còn đơn chuyển khoản QR (`pending_payment`) chỉ gửi thông báo sau khi SePay Webhook xác nhận tiền về thành công; khi khách bấm Thanh toán mà thiếu địa chỉ, phải tự động cuộn lên khung địa chỉ và kích hoạt hiệu ứng rung cảnh báo viền đỏ (`triggerAddressShake`).
7. **[Web Image Quality & Aspect Ratio Framing]** Ảnh sản phẩm tải lên từ điện thoại (`3:4`, `9:16`) hoặc ảnh nhỏ bị mờ, vỡ hạt hoặc bị cắt mất đầu/đuôi sản phẩm trong khung vuông -> Nén canvas 1 bước từ ảnh lớn gây răng cưa (bilinear aliasing) và `objectFit: 'cover'` cắt mất rìa của ảnh chữ nhật -> **Luật bất khả kháng:** Mọi ảnh tải lên trên Web trong `ProductStudioForm.tsx` bắt buộc đi qua bộ kiểm tra Magic Bytes + đổi tên UUID v4 (`fileUploadGuard.ts`) và hàm hạ cỡ đa bước 2x (`optimizeHdImageIfWeb`) về chuẩn khung vuông **Ultra-HD `1440×1440` (1:1)** chất lượng `0.94`, tự động căn vừa khung cho ảnh chữ nhật kèm nền studio mờ để không bao giờ làm mất chi tiết sản phẩm.
8. **[TypeScript CLI & Clean Source Tree]** Chạy lệnh `npx tsc` trực tiếp không có cấu hình chuẩn khi thiếu `expo/tsconfig.base` làm phát sinh hàng loạt file `.js` rác nằm lẫn trong thư mục `src/` -> `tsc` mặc định bật chế độ emit file `.js` nếu không đọc được file cấu hình gốc -> **Luật bất khả kháng:** Không bao giờ để file `.js` biên dịch tự động tồn tại trong `src/` (mọi code trong `src/` chỉ dùng `.ts` và `.tsx`); sử dụng `npm run security:check` và `npm run build:web` (`npx expo export -p web`) để xác thực toàn bộ dự án trước khi commit.
9. **[Database Schema CamelCase Naming & Safe Index Creation]** Chạy SQL tạo Index trong Supabase SQL Editor báo lỗi `ERROR: 42703: column "created_at" does not exist` -> Các bảng trong Supabase (`products`, `orders`, `addresses`, `cart_items`, `favorites`) sử dụng tên cột `camelCase` đặt trong dấu ngoặc kép (`"createdAt"`, `"userId"`, `"fullName"`, `"detailAddress"`) thay vì `snake_case`, hoặc bảng `products` trên môi trường thực tế có thể thiếu cột thời gian tuỳ phiên bản -> **Luật bất khả kháng:** Mọi truy vấn SQL và `CREATE INDEX` bắt buộc viết đúng tên cột `"createdAt"`, `"userId"` có dấu ngoặc kép và bọc trong khối `DO $$ BEGIN ... EXCEPTION WHEN OTHERS THEN NULL; END $$;` để luôn thực thi an toàn 100% trên Supabase SQL Editor.
10. **[Mobile Product Sync & Instant Logout]** Sản phẩm mới đăng trên máy tính không hiển thị trên điện thoại và bấm nút Đăng xuất trên điện thoại không thoát được -> (1) Gắn tham số `&_t=${Date.now()}` vào URL PostgREST (`/rest/v1/products`) khiến Supabase hiểu nhầm `_t` là cột trong bảng và trả về lỗi `400 Bad Request (PGRST100)`, đồng thời tải toàn bộ cột `image,tags` (nặng >20MB Base64) trong 1 request duy nhất gây nghẽn mạng di động; (2) Dùng `window.confirm` khi bấm Đăng xuất bị trình duyệt di động/WebView chặn và `await supabase.auth.signOut()` bị treo khi token hết hạn mà chưa xoá `localStorage` -> **Luật bất khả kháng:** Tuyệt đối không gắn tham số lạ (`_t`) vào URL `/rest/v1/` của PostgREST (chỉ dùng `cache: 'no-store'`), luôn tải danh sách metadata sản phẩm nhẹ trước (`<10KB`) rồi nạp dần `image,tags` theo từng cụm 2 sản phẩm (`hydrateMissingProductMedia`); khi `logout()` bắt buộc phải `setUser(null)` và xoá sạch các khoá `sb-*` trong `localStorage`/`sessionStorage` ngay lập tức mà không chặn bởi `window.confirm` trên Web.
11. **[Deleted Seed Products Reappearing After Redeploy]** Các sản phẩm mẫu gốc (`MOCK_PRODUCTS` trong `src/data/products.ts`) sau khi Admin bấm xoá vẫn tự động xuất hiện lại mỗi khi push code mới / Vercel deploy lại hoặc khi mở trên thiết bị khác -> Danh sách ID sản phẩm đã xoá (`tcl_deleted_product_ids_v1`) chỉ được lưu cục bộ trong `localStorage` của trình duyệt (và bị lỗi `QuotaExceededError` khi `PRODUCTS_CACHE_KEY` chứa chuỗi ảnh Base64 lấp đầy 5MB `localStorage`), hoàn toàn không được đồng bộ lên Supabase nên khi tải lại bản build mới hoặc mở máy khác, `mergeWithMockProducts` tự động nạp lại toàn bộ `MOCK_PRODUCTS` -> **Luật bất khả kháng:** Trong `ProductContext.tsx`, `PRODUCTS_CACHE_KEY` trên `localStorage` chỉ được lưu metadata nhẹ (không lưu chuỗi `data:image/` Base64, nhường toàn bộ ảnh HD cho `IndexedDB`); danh sách sản phẩm đã xoá (`deletedIdsMemory`) bắt buộc phải lưu đồng thời ở 4 tầng: `Memory Set` + `localStorage` + `IndexedDB` (`deleted_product_ids`) + đồng bộ trực tiếp lên Supabase (`public.addresses` dòng `id = 'tcl_deleted_products_v1'`, `fullName = '__TCL_CHAT_MSG_V1__'`) để mọi thiết bị và mọi lần Vercel deploy đều lọc bỏ vĩnh viễn các sản phẩm gốc đã xoá.
12. **[Google Search Favicon & ICO Magic Bytes]** Đã đăng ký Google Search Console và hiện ảnh thumbnail lớn bên phải nhưng icon tròn nhỏ (Favicon) bên trái tên miền trên Google Search vẫn hiện hình quả địa cầu mặc định -> File `public/favicon.ico` thực chất là ảnh `.png` đổi đuôi sang `.ico` (mang Magic Bytes `89 50 4E 47` của PNG trong khi Vercel trả về `Content-Type: image/vnd.microsoft.icon` kèm `X-Content-Type-Options: nosniff`) khiến bot `Google-Favicon` từ chối giải mã file `/favicon.ico`, cộng thêm thiếu file `public/sitemap.xml` -> **Luật bất khả kháng:** File `public/favicon.ico` bắt buộc phải có cấu trúc nhị phân `MS Windows icon resource` thật (`00 00 01 00` ICONDIR header chuẩn 48x48, tuyệt đối không đổi tên trực tiếp từ `.png` sang `.ico`), đi kèm các thẻ `<link rel="icon">` bội số 48px (`48x48`, `96x96`, `192x192`) trong `src/app/+html.tsx` và `public/sitemap.xml` hợp lệ.
13. **[Buy Now Packaging & Variant Price Sync]** Khi khách bấm "Mua ngay" (`mode=buy_now`) ở trang chi tiết sản phẩm có chọn "Hộp quà + Thư tay (+15.000₫)" hoặc chọn mẫu có giá riêng nhưng sang trang Thanh toán (`checkout.tsx`) lại hiện "Không hộp" và chưa cộng 15.000₫ -> Hàm `buyNowProduct` trong `src/app/checkout.tsx` chỉ lấy `base.price` gốc và gán cứng `selectedAccessoryName: undefined` thay vì đọc `selectedColorId`, `selectedAccessoryId` và cộng `accessoryDelta` (`+15.000₫`) + `matchedColor.price` -> **Luật bất khả kháng:** Mọi thay đổi về cách tính giá biến thể (`colorOptions.price`) hoặc phụ kiện đóng gói (`selectedAccessoryId === 'gift_box_letter'` `+15.000₫`) bắt buộc phải cập nhật đồng bộ ở cả 3 luồng: Giỏ hàng (`CartContext.tsx`), Mua ngay (`buyNowProduct` trong `checkout.tsx`) và Server (`api/orders-guard.js`).
14. **[Supabase Egress Quota & Polling Protection]** Dự án Supabase Free Tier bị khoá `402 Payment Required (Egress Exceeded - 5GB/month)` -> `ProductContext.tsx` chạy `setInterval(syncProducts, 30000)` + `focus` listener kết hợp kiểm tra `!Array.isArray(cached.colorOptions)` (luôn `true` với sản phẩm không có `colorOptions`) và gọi `select=id,image,tags` với `cache: 'no-store'` khiến trình duyệt tải lại hàng chục MB ảnh Base64 mỗi 30 giây -> **Luật bất khả kháng:** Trong `ProductContext.tsx`, bắt buộc đánh dấu `coverChecked: true, tagsChecked: true` trong `hydratedMediaMemory` ngay khi nạp từ `IndexedDB` hoặc sau lần fetch đầu tiên, ở Pass 2 chỉ gọi `select=id,tags` (tuyệt đối không tải lại cột `image`), và giãn chu kỳ đồng bộ nền tối thiểu `300.000ms` (5 phút) có throttle `focus` `120.000ms`.
15. **[IndexedDB Hydration Race Condition & Custom Product Rescue]** Khi chuyển sang project Supabase mới hoặc tải lại trang, một số sản phẩm Admin tự thêm trước đó bị mất khỏi `IndexedDB` (`custom_products` / `cached_all_products`) -> `syncProducts()` hoàn tất trước khi `idbHydrationPromiseRef.current` đọc xong mảng ảnh Base64 lớn từ `IndexedDB` rồi gọi `removeCustomAdminProduct(rId)` và `saveCachedProducts(merged)` ghi đè lên `IndexedDB` bằng dữ liệu rỗng/thiếu từ `localStorage` (vốn bị giới hạn 5MB) -> **Luật bất khả kháng:** Trong `ProductContext.tsx`, `syncProducts()` bắt buộc phải `await idbHydrationPromiseRef.current` trước khi hợp nhất dữ liệu hoặc gọi `saveCachedProducts`; `removeCustomAdminProduct(id)` chỉ được ghi lại `IndexedDB` nếu `customAdminProductsMemory.delete(id)` trả về `true`, đồng thời tự động khôi phục mọi sản phẩm `user_` từ `cached_all_products` vào `customAdminProductsMemory` và đẩy tuần tự (`await upsertProductToSupabase`) lên Supabase.
16. **[Geolocation CSP & Vietnam 3-Tier Address Resolution]** Khi bấm "Lấy vị trí" ở trang Thêm địa chỉ nhận hàng (`/addresses/add`) trên macOS Chrome hoặc WebView vẫn bị báo lỗi đỏ `"Trình duyệt đang chặn quyền vị trí"` dù đã mở quyền GPS -> (1) `https://api.bigdatacloud.net/data/reverse-geocode-client` thực hiện `307 Temporary Redirect` sang `https://api-bdc.io/data/reverse-geocode-client` khiến trình duyệt chặn tiếp theo `Content-Security-Policy` (`connect-src`) nếu thiếu `https://api-bdc.io`, đồng thời `nominatim.openstreetmap.org` bị một số nhà mạng Việt Nam chặn kết nối (`exitCode: 7`); (2) Khi `getBrowserCoordinates()` thành công nhưng cả 2 API reverse-geocode bị chặn, hàm không fallback sang IP/Photon và nhận diện nhầm `localityInfo.administrative` level 6 (`Long Bình` - phường) với `localityInfo.informative` (`Thành phố Thủ Đức` - quận/TP thuộc tỉnh) -> **Luật bất khả kháng:** `connect-src` trong `vercel.json` bắt buộc khai báo đầy đủ `https://api-bdc.io`, `https://api.bigdatacloud.net`, `https://photon.komoot.io`, `https://provinces.open-api.vn`, `https://ipwho.is`, `https://ipapi.co`; `useAutoLocation.ts` phải gọi trực tiếp `https://api-bdc.io` + `photon.komoot.io` + `nominatim` có `AbortController` timeout 2.5s, phân tích cả `administrative` lẫn `informative` để tách chuẩn `TP. Thủ Đức`/Quận/Huyện và `Phường/Xã`, kèm fallback IP an toàn ngay cả khi GPS có toạ độ.
17. **[Product Detail & Synthetic Combo Schema Completeness]** Khi bấm vào thẻ sản phẩm / Combo chuyển sang trang `/product/[id]` bị văng màn hình trắng -> Đối tượng `Product` tổng hợp (`buildCuratedComboProducts`) thiếu trường `rating` / `reviews: []` hoặc phần tử `colorOptions` thiếu `id` chuỗi khiến `product.rating.toFixed(1)`, `product.reviews.length` và `opt.id.startsWith(...)` ném lỗi `TypeError: Cannot read properties of undefined` -> **Luật bất khả kháng:** Mọi hàm khởi tạo hoặc chuẩn hoá `Product` (`comboCatalog.ts`, `comboPricing.ts`, `ProductContext.tsx`) bắt buộc gán đầy đủ `rating: 5.0`, `reviews: []`, `id: String(c.id || ...)` và trong `src/app/product/[id].tsx` luôn bọc `(Number(product.rating) || 5.0).toFixed(1)` cùng `Array.isArray(product.reviews) ? product.reviews : []`.
18. **[Mobile WebKit OOM Crash & IndexedDB Structured-Clone Throttling]** Mở web trên điện thoại (iOS Safari / Mobile Chrome) liên tục bị báo lỗi `"Đã xảy ra sự cố trên trang web này"` và tự tải lại trang -> Trong `hydrateMissingProductMedia` (`ProductContext.tsx`), vòng lặp 11 cụm sản phẩm gọi `setProducts(merged)` và `saveCachedProducts(merged)` (`saveToIdb` 25MB ảnh Base64) ngay bên trong vòng lặp `for` khiến trình duyệt di động phải cấp phát bộ nhớ `structuredClone` `11 × 25MB = 275MB` cùng lúc, kết hợp vẽ `<canvas>` ngầm khi chọn mẫu Combo làm tràn giới hạn RAM ~300MB của tiến trình Mobile WebKit -> **Luật bất khả kháng:** Tuyệt đối không gọi `saveCachedProducts` hoặc `setProducts` lặp lại bên trong vòng lặp nạp từng cụm `tags` (chỉ gom vào `hydratedMediaMemory`, nghỉ `60ms` giữa các cụm cho Garbage Collector, rồi gọi `setProducts` + `saveCachedProducts` có debounce `900ms` đúng 1 lần sau khi kết thúc vòng lặp); hiển thị khung ghép đôi Combo bằng Flexbox/DOM (`ComboStudioLiveView`) thay vì tự động tạo `<canvas>` Base64 trong `useEffect`.

## 5. SHORTCUT TRIGGERS (LỆNH TẮT & CHẾ ĐỘ MẶC ĐỊNH)

### 1. KHI CÓ TỪ KHÓA Ở ĐẦU CÂU:
- **`fix: [lỗi]`** *(Sửa lỗi/bug)*: Tìm nguyên nhân gốc để sửa -> Quét toàn dự án xem có chỗ nào bị tương tự không để sửa luôn -> Chạy typecheck/build (`npm run security:check` / `npm run build:web`) -> Bắt buộc ghi bài học vào mục **"4. SELF-EVOLVING MEMORY"**.
- **`edit: [yêu cầu]`** hoặc **`sửa: [yêu cầu]`** *(Chỉnh sửa giao diện, text, logic, cấu hình sẵn có)*: Kiểm tra ảnh hưởng để không làm hỏng tính năng cũ -> Thực hiện chỉnh sửa -> Chạy typecheck/build kiểm tra.
- **`add: [yêu cầu]`** *(Thêm tính năng/tiện ích mới)*: Lên phương án (Pha 1) -> Viết code kèm đủ trạng thái `Loading/Success/Error` (Pha 2) -> Chạy typecheck/build (Pha 3).
- **`opt: [yêu cầu]`** *(Tối ưu tốc độ/hiệu năng)*: Đo lường & tìm điểm nghẽn -> Tối ưu code/query mà không làm gãy **CRITICAL PATHS** -> Chạy build kiểm chứng.
- **`audit`** *(Kiểm toán nhanh)*: Rà soát lại hiệu năng, UX và bảo mật của các file vừa sửa trong `git diff`.

### 2. CHẾ ĐỘ TỰ NHẬN DIỆN (DEFAULT FALLBACK - KHI KHÔNG GÕ TỪ KHÓA):
Nếu người dùng chỉ gõ một câu yêu cầu bình thường bằng tiếng Việt mà không có từ khóa ở đầu:
- Tự động phân tích ngữ cảnh câu nói để xếp nó vào đúng nhóm (`fix`, `edit`, `add`, hoặc `opt`) và **TỰ ĐỘNG chạy ngầm đầy đủ quy trình 3 pha + kiểm tra build + tự học (nếu là lỗi)** của nhóm đó mà không được bỏ qua bất kỳ bước bảo vệ nào.
